# Saturday UI design guide

Saturday is a local SvelteKit app with a restrained glass navigation layer and solid content surfaces. CSS approximates translucent materials; it does not provide native refraction or system vibrancy. Use existing components and tokens so new pages behave consistently.

## Materials, geometry, and navigation

`src/routes/layout.css` owns light/dark tokens, materials, radius scale, responsive geometry, and primitive overrides. `src/routes/+layout.svelte` owns navigation, the scroll edge, toast host, and route transitions.

Reserve glass/blur for the functional layer: top bar, tab bar, toast, dialog, and scroll edge. Use solid surfaces for cards, lists, statistics, fields, buttons, disclosures, and history. Selection uses a tinted fill without another blur layer.

| Token         | Value | Use                                         |
| ------------- | ----- | ------------------------------------------- |
| `--r-shell`   | 28px  | Top/tab bars, dialogs, toasts, empty states |
| `--r-card`    | 24px  | Cards, disclosures                          |
| `--r-group`   | 16px  | Insets, notices, code blocks, callouts      |
| `--r-control` | 12px  | Fields, selects, compact buttons            |

Use `rounded-[var(--r-group)]` and the other tokens, not Tailwind's numbered/named radius scale for app surfaces. Nested surfaces step down; navigation items use the existing concentric radii (18px top bar, 22px tab bar).

Navigation contains Dashboard, Jobs, Network, Documents, and Settings. Extensions appears before Settings only when enabled. Profile belongs under Documents, with no separate top-level tab. Keep icons and visible labels consistent across sizes.

At 48rem and wider, navigation is in a sticky top bar with a blurred scroll edge. The top bar is an inline-size container: below 64rem of internal width, links stack icons above labels to keep five or six destinations clear of the brand; wider bars use icons beside labels. Below 48rem, use the floating bottom tab bar; the brand row is non-sticky. The tab bar scrolls horizontally when necessary. Preserve content padding and safe-area clearance. Hover fills belong inside `@media (hover: hover)`.

## Building a new page or feature

Read this guide, then start from the closest existing page: Jobs for a filtered list, Network detail for linked records, Add job for a form, Settings for sections. Check `src/lib/components/app/` before writing markup; reuse a component or extract a repeated pattern.

| Need                           | Use                                                                  |
| ------------------------------ | -------------------------------------------------------------------- |
| Page frame and title           | `PageShell`, then `PageHeader`                                       |
| Back navigation                | `PageHeader`'s `back={{href, label}}` prop                           |
| Labelled input/select/textarea | `Field` with `Input`, `NativeSelect`, or `Textarea`                  |
| Checkbox/radio                 | `Checkbox`, `RadioOption`                                            |
| Record lists                   | `Card` with `JobRow`, `PersonRow`, `AttentionRow`, or `DocumentRow`  |
| Due dates                      | `DueBadge`                                                           |
| Detail sections                | `SectionCard`, `LinkedItem`, `EmptyState size="inline"`              |
| Search and paging              | `FilterBar`, `FilterChips`, `Pagination`                             |
| Search input                   | `SearchField` (icon, clear control, 44px target)                     |
| Picker "nothing matched" line  | `SearchEmpty` ("No matching people. Add a person…")                  |
| Tag search                     | `TagSearch` (shared by `TagPicker` and Settings tag lists)           |
| Filter wording, counts, chips  | `$lib/filter-labels.js`, `$lib/filter-chips.js`                      |
| Per-item actions               | `RowActions`, `ActionMenu`                                           |
| Consequential confirmation     | `ConfirmDialog`                                                      |
| Form progress and error focus  | `enhanceWithFocus` or `withPending` from `$lib/forms`                |
| Unsaved edits                  | `UnsavedChanges`, `UnsavedGuard`                                     |
| Shared create/edit fields      | `JobFields`, `PersonFields`, or the relevant shared fields component |
| Date/size display              | `formatDate`, `relativeDay`, `formatBytes`, `formatDateTime`         |

`PageShell` supplies spacing and `{title} · Saturday`; use `width="form"` for forms. Contextual titles read `Ada Lovelace · Network`. `PageHeader` supports eyebrow, description, metadata, actions, and back navigation. Allow actions and long titles to wrap. Job detail uses two columns from 64rem and one below it.

Keep reusable fields independent of transport. Pass domain data, bound drafts, errors and callbacks into controls such as `JobHistoryFields` and `ReminderFields`; do not import server services, `$app/forms` or navigation into field components. Shared activity draft builders live in `src/lib/activity-drafts.js`. Pages and web dialog compositions own SvelteKit enhancement, form action URLs, redirect handling, pending state and error focus. Preserve native form submission wherever currently supported. Another platform can bind the same validation and draft state to its own submission adapter without copying field rules. See the [application boundaries](application-architecture.md).

`FilterBar` is one solid card kept short so results start high on the page. Its primary row holds the search field, quick selects and Sort; with an advanced panel the row ends with `FilterToggle`, a button styled like the neighbouring fields (control radius, field border, 44px) with an applied-count badge, so it reads as part of the row rather than a prominent action ("Advanced filters" on Jobs, "More filters" on Network). The toggle is a real disclosure button (`aria-expanded`, `aria-controls`) and sits last in the primary row so tab order matches the visual order (own row on a phone, beside the selects on a tablet, end of the row on a desktop); below 24rem the controls stack. The panel is hidden (an `is-collapsed` class, not the `hidden` attribute, because Tailwind's preflight would defeat the no-JavaScript override) until it is opened, or opens by itself when an advanced filter is applied or has an error. Without JavaScript the toggle is hidden and the panel and footer are always shown (a `<noscript>` rule in `FilterBar`). The footer (Clear and Apply, plus a "Changes not applied yet" cue) appears only when it has something to do: applied chips, unapplied edits or an open panel. Forms without an advanced panel (Documents, Profile, Recovery) have no panel and no footer: Search and Clear sit beside the field. Applied chips sit above the footer, on one horizontally scrolling line below 48rem. The result count is a separate line above the list, not part of the card. Apply stays secondary because the page header owns the primary action. Below 48rem the panel scrolls into view when opened and the footer sticks above the tab bar while it is open. Every "No matching …" empty state uses `noMatchHint` ("Try fewer filters or clear them." or "Try a different search or clear it."). Links into Jobs from other pages come from `allJobsUrl`, `stageJobsUrl` and `milestoneJobsUrl` in `$lib/job-search.js`, never hand-written query strings. Network accepts Jobs-style `follow_up=any` and `unset` and redirects them to `all` and `not_scheduled`. Filters and search share one vocabulary from `$lib/filter-labels.js`: "Any" means unrestricted; the Apply button reads "Apply filters" (search-only forms use "Search" and "Clear search"); counts come from `resultCount` ("3 jobs matching filters"); a reminder that is empty reads "Not set" whether the URL says `unset` or `not_scheduled`. Build chips with `buildChips`/`tagChips` for URL-parameter lists, never by hand; chip remove targets are 44px. Omit `FilterBar`'s `action` to submit to the current page, never pass an empty string. `FilterBar` supports an `instant` mode: a select or toggle marked `data-instant` applies on change with `replaceState`, keeping focus and scroll, while text search and advanced fields still wait for Enter or Apply. `navigate` makes Apply and Enter load results client-side, keeping focus, scroll and an open dialog (the Profile document picker uses it). Network's Reminder and Sort apply instantly; reminder wording comes from `reminderLabel` ("Any", "Not set"). Dialog pickers use `SearchField` and `SearchEmpty` but keep their own layouts. The form stays a native GET form, so it works without JavaScript.

Rows follow the shared `.list-row` grid. Job/person/date rows are whole-row links; document rows contain separate actions. Secondary text must be at least 13px (`.meta-text` or `text-sm`). Show job/person `#123` references beside names in rows, headings, linked records, and pickers; pass IDs explicitly rather than parsing URLs.

Use `.link` for content links. Headings use balanced wrapping, paragraphs use pretty wrapping, and counts use natural language. Inline `code` receives its chip style automatically. Posting links show the host, full-address tooltip, and an accessible new-tab cue. Long saved text uses native Show more/Show less disclosures so the full content remains reachable without JavaScript; native summaries expose their expanded state.

## Buttons and forms

- Keep at most one tinted primary action per view/header. If an empty state repeats that primary action, hide the duplicate header action.
- Prominent actions inside `.page-actions`, `.form-actions`, `Dialog.Footer`, and EmptyState use capsules. Other controls use `--r-control`. The shared Button exposes `data-variant` for styling.
- Use `default` for primary, `outline` for secondary, `ghost` for Cancel/low emphasis, and `destructive` for permanent deletion. Stage changes use ordinary action styling; permanent history deletion uses destructive styling.
- Pair Create/Upload/Link actions with `Plus`/`Upload`/`Link2`. Icon-only buttons require an accessible name and title.
- Use shared labelled controls; never hand-write bare `<label>`, `<select>`, checkbox, or radio elements in page code.
- Add/Edit forms share field components. Mark required fields with `*` and include a “* Required” cue.
- Additional optional fields use `.disclosure` / `.disclosure-body`. Keep job title/company, posting link, description, notes, and star visible; employment details belong in the disclosure.
- Footers use `.form-actions`, primary last; add/edit pages align actions to the end.
- Wrap custom `use:enhance` callbacks in `withPending`; `enhanceWithFocus` already does this. Show submit progress and focus the first invalid field or error Notice on failure. Use `focusFirstError()` in custom callbacks.
- Free-text forms use `UnsavedChanges`, `guard.enhance`, `oninput={guard.markDirty}`, and `UnsavedGuard`. Document editors also show an unsaved badge.

Explain conditional behavior in a field hint where needed. Preserve drafts and selections after validation failure. An expired-session response retains the draft, resets saving/progress state, and allows manual retry after separate-tab sign-in. Every action URL, including Star, Save, Clear and history corrections, must retain its validated originating Dashboard/Jobs context and applied filters/pages. A mutation must not silently replace it with a default destination.

## Dialogs and feedback

Dialogs use centered glass panels at desktop widths and bottom sheets below 48rem, with a dimmed backdrop and solid controls. Always include a title and description. Use `sm:max-w-md` for short forms/confirmation, `sm:max-w-lg` for longer forms, and `sm:max-w-2xl` for pickers. Stack footer buttons below 48rem and use a row at 48rem and wider, matching the sheet breakpoint. Cancel uses ghost styling. Where present, desktop removal actions sit left, with Cancel and Save right; mobile order is Save, Cancel, then Delete/Clear, with full-width controls.

Use `ConfirmDialog` for consequential actions; it submits the form identified by `formId`. Never use `window.confirm`. Keep corrections consistent with the feature’s add/edit flow. Use dialogs for short stage/history/reminder/relationship-note updates and dedicated pages for substantial Add/Edit job or person forms. Short job updates match Network reminder and interaction styling. Use UnsavedDialog with an UnsavedChanges guard for short reminder/interaction and relationship-note forms; wire Cancel to its provided close callback and preserve dirty/saving state through enhanced submissions. Keep dialog errors inside the dialog and preserve focus on failure. Toasts sit below dialog overlays so a previous success message cannot cover a mobile form action.

`RowActions` exposes Edit with icon/text; other actions use `ActionMenu`, with permanent Delete tinted, separated, and last. Parent job/person deletion belongs in the detail header menu and one `ConfirmDialog`, with Cancel initially focused and focus returned to the menu trigger on dismissal. Explain history/reminder/relationship deletion and all job documents; keep counts informational because confirmation includes current data at execution. Use pending guards for all dismissal paths and distinguish cleanup-recovery feedback from pre-commit failure. Empty states explain the next step and offer one primary action.

Successful server saves redirect with `?saved=<key>` from `SAVED_MESSAGES` in `$lib/toast.svelte.ts`; the layout shows the toast once and removes the parameter. Client actions can call `toast.show(message)`. Use `Notice` for errors and persistent information; error notices need a title, `role="alert"`, and a focus target. Long-running Settings operations use their existing status notices.

## Feature patterns

### Dashboard and Jobs

Dashboard shows today's date with no header actions (Add job and Add person live on Jobs and Network; only the empty workspace offers Add job). When anything is overdue or due today, an `.attention-summary` row of links ("3 overdue", "1 due today", never active-job counts) jumps to Needs attention. Then a full-width read-only Job pipeline with View all jobs. Below it, use two columns from 64rem: Needs attention and Coming up on the left (their own headings, no Notifications wrapper heading) and Milestone history on the right. Stack those before Milestone history below 64rem. The board's stage counts replace the separate Active now summary. The board makes every unarchived stage available, including empty and closed stages, with full current counts and independent 20-card pages sorted by latest change. Use semantic headings/lists, shared Pagination, stable stage-ID pagination URLs and column focus after job paging. Show only as many complete stages as fit, with previous/next stage controls on the same row as the stage-position text beneath the board at every screen size, with no horizontal scrollbar. Support horizontal touch swipes and trackpad gestures that advance one stage at a time; retain native vertical list/page scrolling and pinch zoom. Stage headings and their links support Left/Right keyboard navigation, revealing and focusing adjacent stages while leaving job-list keys unchanged. Align the first stage with the leading edge and the last stage with the trailing edge, keeping column widths stable and reserving preview space only on the available side. Render at most one adjacent stage preview on each available side and apply a subtle fade at their outer edges, keeping the neighboring surface recognizable and visible stages fully readable. Previews must be inert and hidden from assistive technology. Slide the stage track horizontally during local stage browsing, preserving paging/focus and skipping motion when reduced motion is requested. Horizontal browsing must not change the URL, add browser-history entries, fetch stage data, or scroll the page. Trusted wheel gestures count as user activity through the existing throttled session tracker when password login has a finite inactivity limit; session checks are separate from carousel data navigation. Retain the tallest measured board height until the viewport width changes, so short/empty stage windows do not pull controls and following sections upward. Column backgrounds stretch to that height so the board reads as one even band; card lists keep their natural height inside. Keep route cross-fades disabled for Dashboard job pagination; horizontal browsing owns its local slide motion. Below 48rem show one complete stage with neighboring previews; keep columns consistently readable rather than shrinking their contents while browsing. Keep the visible stage window in local component state; returning to Dashboard may reset it. Preserve independent job pages in URLs and reveal the paged stage from its anchor. Without JavaScript, View all jobs provides access to every stage and ordinary job pagination remains available in the initial stage. Stage names link to their current-stage Jobs filter. Cards have exactly two visible, ellipsized lines: role (with a filled star for starred jobs) and company (with a destructive dot for an overdue reminder and a trailing "5d" days-in-stage, omitted in closed stages); signals repeat in the link's accessible name; put the job number in the accessible link name and full text in the tooltip. A stage list taller than 25rem scrolls and fades the edge that has more cards (scroll-driven mask; nothing fades when the list fits). Keep compact shared Pagination for job pages within a stage. Initiate stage changes from job detail and omit drag affordances, layout toggles and Dashboard filters. Keep configured stage order without extra open/closed labels on the board. Archived history belongs in a compact disclosure, without board columns. Stage names/order come from storage, with open stages before closed destinations. Milestone totals count distinct jobs including closed jobs and scheduled entries, link to `/jobs?view=all&milestone_stage=<id>`, and stay distinct from current placement. Archived history remains searchable. Show readable date/DueBadge cues; status never relies on color alone. Dashboard remains an overview without stage mutations. Needs attention is one time-ordered list grouped Overdue, Today, Upcoming (`buildAttention` in `$lib/dashboard-attention.js`) of `AttentionRow`s: a type icon tile (bell reminder, person network reminder, flag deadline, calendar milestone), title, subtitle, note and a date chip that reads relative ("3 days overdue", "Tomorrow · 09:00", "Due in 2 days") with the full date as its tooltip; the chip sits at the row end from 40rem and under the text on a phone. Show five rows, the rest behind a native `.disclosure` "Show N more"; every non-empty group gets at least one of the five (`splitAttention`), so Today and Upcoming are never hidden by a long Overdue list, and the disclosure repeats group headings as "Overdue · 4 more". Notes clamp to two lines (full text in the tooltip). The Dismiss check uses the foreground colour so it stays visible. Reminder rows carry a separate 44px Dismiss check button (never a button inside the row link): scripts post `?/dismiss` with `enhanced=1` and show an Undo toast (`toast.show(text, { action })`, `?/restore`), a plain form redirects with a toast. Milestone history rows show the count and a proportional bar (share of all jobs; muted for closed stages; Highlight in forced-colors) and stay expanded at every width.

Jobs is list-only with a visible Search jobs field, URL/chip state, sort choices and Pagination. One Status select offers Active, Closed, All and each unarchived current stage (stable stage IDs, submitted as `status`; the canonical URL still uses `view` and `current_stage`). Status and Sort apply instantly (Starred, with Advanced filters, applies instantly too) through `FilterBar`'s `instant` mode; Search applies on Enter; Advanced filters apply with the GET Apply button, and `unapplied` shows a cue while the draft differs. Multi-select categories in the panel (work arrangement, employment type, created via, milestone history) are pill toggles (`.choice-pills` on the group, 44px, tinted fill plus a check mark when selected, system colors in forced-colors mode). Once scripts run, Date range From/Through show only when Date range is selected and Score Minimum/Maximum only when Scored (or when a bound is already in the URL); without scripts every field stays visible. The advanced panel is grouped into Details, Job type and history, Tags, Dates and Assistant score, with an applied count in the summary and auto-open when any advanced filter is applied. Milestone history uses stable stage IDs and, while selected without a stage, sets Status to All and locks it with a hint. Use Active/Closed/All labels. Rows open detail with validated internal return URLs; preserve filters/pages across edits and show an explanation if changed placement leaves the original results.

Job detail uses an 18rem left sidebar from 64rem for compact Reminders and Job details, with History, Documents, Network and Job description in the main column. The DOM follows that same order on mobile; Job details initially opens on desktop and collapses on mobile. Metadata starts on its own row below the title/company, ordered current stage, optional Score button, then Added by assistant when applicable. The score button opens read-only assessment notes; hide missing scores but show zero. Do not reserve title space for a score tile or imply a fixed scoring scale. Location, work arrangement, employment type and dates remain in Job details rather than expanding this row. Limit initial history to five recent and three upcoming entries and document previews to three files, using native Show more disclosures for the remainder and Manage documents beyond the loaded preview. Bound long descriptions, timeline notes, reminder notes and job notes with the shared ExpandableText disclosure.

On job detail, Change stage is primary; Add history, Edit and Star/Unstar are secondary. Change stage, Add history, Edit history, and Add/Edit reminder open shared dialogs with the same glass panel, responsive bottom sheet, labelled controls, spacing and Cancel/Save footer as Network. Use compact three-row note fields; keep Add/Edit job on dedicated pages. Change stage saves placement and a milestone together; Add history records a note/past/scheduled milestone without moving the job. Timeline entries show a small ghost Edit history button with a Pencil icon opening a prefilled dialog, with confirmed Delete history inside. Preserve drafts and focus on validation/authentication failure. Ask before dismissing unsaved edits through Cancel, Close, Escape or the backdrop, and protect navigation while editing. Successful saves close the dialog, refresh detail, and preserve the original Dashboard/Jobs context. Keep required cues, distinct help and success feedback. Do not add dedicated Dismiss/Reopen buttons or a second placement field to ordinary editing. History edit/delete never changes placement and blocks removal of sole current-stage evidence with Change stage first guidance. Keep future Scheduled and retired Archived cues readable.

### Tags

Use shared TagChip, TagList, TagPicker and TagDefinitionFields for separate Job tags and People tags collections. Display canonical underscore-separated names with spaces and lowercase text, including accessible names and previews. Metadata chips are noninteractive labels; in pickers one list of toggle chips shows every tag, with the selected ones tinted and checked, so there is no separate selected row or Remove control; filter choices expose checked state. Follow the [Material chip patterns](https://material-web.dev/components/chip/) within Saturday's existing tokens rather than importing another component library.

Render the saved six-digit hex color as a soft tint, not a solid fill: about 14% of the color over the card surface (`color-mix`), a 40% border and a solid dot (`.tag-tint`, `.tag-dot` in `layout.css`, set `--tag`), with the label in the normal foreground color so contrast never depends on the chosen color. Keep theme-aware borders/focus visible. Custom colors never indicate selection or destructive intent alone. Offer the curated `tagPalette` swatches (44px toggle buttons with `aria-pressed`) plus a Custom native color input synchronized with the hex field, preserving invalid text drafts. Interactive targets are at least 44 CSS pixels; wrap chip groups and expose complete long names. In forced-colors mode use system colors. Unchecking a tag changes the draft assignment, not its reusable definition; an unavailable tag stays in the list so it can be unchecked. Preserve focus by tag ID during selected-first sorting. The picker shows its search field only for single-choice pickers or more than 12 tags; search runs as you type after a short pause (no Search button), and when the search has no exact match and creation is allowed it offers a Create “name” chip beside the standard Create a tag button.

Tags occupy a compact wrapping row below detail-header metadata. List rows show two tags (three from 48rem) plus a neutral +N chip whose tooltip and screen-reader text name the hidden tags, with no nested links/buttons; Dashboard's two-line pipeline cards stay unchanged. Short assignment/definition/merge forms use UnsavedDialog with the standard responsive footer and retained drafts after validation/authentication failures. Inline creation uses a separate request without nested forms or accidental parent submission. Settings has one Tags section with two independent collection groups, search/paging, editing and exactly-two-tag merging. Delete belongs inside Edit tag and uses ConfirmDialog; merge explains removal and reference impact before the final Merge tags button.

### Network

Use solid lists/cards, shared person fields, GET filters, and independent pagination for linked jobs and interactions. Name is required. Distinguish Person Notes, Relationship note, and Interaction note. Keep role/organization, last recorded interaction, and the next reminder readable on narrow screens. Person detail and editing preserve validated originating Network filters/pages or the linked job and its original Dashboard/Jobs context; direct or invalid origins fall back to Network. Keep independent detail pages through edit/save/cancel and ordinary detail mutations.

Choosers use explicit selection and confirmation, paginated search, and disabled already-linked choices. Link person (job detail) and Link to job (network detail) are one `LinkPicker` dialog (`sm:max-w-lg`, scrolling body, pinned header and footer) fed by thin wrappers; options are `RadioOption` cards (its `initial` variant) (36px initials tile, title with `#id`, a details line, a stage `StatusBadge` for jobs, an "Already linked" badge, a check when selected) on solid `--card` surfaces, never transparent rows over the glass. Search runs as you type after a short pause and on Enter, with no Search button; a live count ("8 people", "1 job matching search") and an Add person/Add job button sit under the field; the list holds one page of five cards in a `max-h-[25rem]` region; the primary button names the choice ("Link Ada Lovelace"). Add job from a person carries `person_id` through `/jobs/new` and returns to `/networks/<id>?link_job=1&job=<id>` with the job selected. Creating a person does not implicitly link them. The job-detail Link person picker keeps search, radio selection and the optional three-row relationship note together in one dialog. Use one Search people field matching name, role or organization, five results per page, and the same dialog width, field spacing and padding as Change stage. Selecting a person must not hide fields, switch layouts or resize the dialog. Keep a selected person available as a radio choice when browsing other results. Bound the results list height so the note remains close to the search; the body can also scroll on short screens while the standard Cancel/Link person footer stays visible. Preserve selection, note, URL context and page state through search/paging and failed/expired saves. Use UnsavedDialog for Cancel/Close/Escape/backdrop/navigation protection; keep the ordinary desktop footer row and stacked mobile actions. A newly created person returns selected and still requires confirmation. Unlink preserves both records. Reminder/interaction dialogs use existing focus handling and compact three-row notes. Jobs and Network share RemindersSection, ReminderFields and the reminder editor. Active reminder cards show Dismiss reminder and Edit reminder; past cards show Edit reminder only. Confirmed Delete reminder stays inside both editors, with the standard Delete/Cancel/Save footer. The Active checkbox restores dismissed reminders; ordinary past edits preserve inactivity. Add reminder visibly defaults Time to 00:00; cards and summaries hide midnight but forms retain it. Schedules stay fixed, with server-local overdue checks. Change stage, Add history and Add interaction offer optional ActivityReminderFields and save both records atomically. Network rows expose Edit interaction; confirmed Delete interaction belongs inside that editor. Cancelling confirmation or failing deletion keeps the edit draft. Shared `.dialog-edit-actions` footers align destructive actions left and Cancel/Save right at 48rem and above; buttons stack at full width below it.

### Documents and Profile

Documents uses DocumentRows in a Card with a FilterBar: Search filenames, Type and Sort by (the last two apply instantly; options come from `documentKinds` and `documentSorts` in `$lib/file-types.js`, and an unknown `type` or `sort` in the URL falls back to Any and Name). Upload is primary; New document and Profile are secondary. Rows show filename, designation badges, type, size, date, Edit, and the action menu. Editor toolbar buttons have accessible labels, `aria-pressed` where relevant, and disabled Undo/Redo when unavailable.

Profile has one solid SectionCard per designation. Show the selected filename or a brief empty state, with compact Select document, Upload, and Create new actions. Reuse existing pickers/editors; template slots create HTML, other slots Markdown. Edit stays visible; Clear selection uses a confirmed menu action and keeps the file.

Existing-document selection keeps search/paging in the URL. Copy to this job loads in place with a skeleton. Network/job pickers also retain URL state for reloads and validation.

### Settings

Section navigation is grouped in page order: General (Preferences), Job search (Workflow, Tags), Assistant (Assistant, Extensions), Data (Backups, Storage), Security and access (Password, LAN access) and Application (Updates, Server, Uninstall). In the desktop sidebar each group has a small muted uppercase label (no icon, no hover, not a link) and a divider above it; the links beneath it have a 16px icon, foreground-colour text, and, when current, the same tinted selection fill, bold label and accent-coloured icon as the top navigation (no accent bar); on the page each group is a `.settings-group` (role group) with a `.settings-group-label` heading rule above its cards and extra space between groups. Below 64rem each group ends with a Back to top link. Titles match the navigation labels. Each section uses SectionCard inside `.settings-layout`. From 64rem the navigation is a sticky left sidebar beside a content column capped at 52rem; below that a sticky section picker bar (clearing the sticky top bar at 48–64rem) names the current group and section and opens the same grouped list as a bottom sheet above the tab bar (backdrop, Escape and outside tap close it and return focus to the bar; picking a section scrolls and closes; the current section is scrolled into view). Without JavaScript the bar is a native disclosure of the same links. The current section carries `aria-current="location"`, driven by scroll position. Preferences holds Appearance and Recently viewed as `.settings-subsection`s (the `#appearance` and `#navigation` anchors still work). Optional extras use the quiet expander (`.disclosure.disclosure-quiet`: a chevron and label, not a bordered bar); `.disclosure` bars remain for content-heavy disclosures elsewhere. Tag lists show their search field once a collection has 12 or more tags.

Save model: toggles and selects that cannot fail halfway (Appearance, Recently viewed) save as they change, with a no-JS Save button inside `<noscript>`. Forms with a Save button (login startup, extensions, inactivity timeout) disable it until a field differs from the saved value (`trackChanges` in `$lib/forms.ts`; without JavaScript the button stays enabled). State is shown as `.status-row`s (label left, value right) before any controls. Host-only controls (updates, server, login startup, LAN, password, uninstall) render as status when the browser is not the host or setup is unfinished; one page banner explains why, and the sections do not show disabled buttons. The destructive Uninstall lives in its own `.settings-danger` card at the bottom. Storage lists Data directory (Open folder), Database file (Copy path) and Documents as rows; Diagnostics is a quiet disclosure. Assistant shows connection status, then a primary Copy configuration, with the JSON, TOML and setup steps in quiet disclosures. Backups lists Create a backup, any restore previews, the Saved backups list (Download, Restore, Delete; an empty state when none), then quiet disclosures for Import a backup and Advanced file recovery.

- **Workflow:** compact grouped rows (Open stages, Closed stages, Archived stages), each a flex row: name with Starting stage/Closed cues and a job-count link, then 44px up/down icon buttons and Edit (icon only below 40rem). Edit is a link to `?edit_stage=<id>` so it works without JavaScript; the panel below the row holds Rename, Closes the job and Archive. A failed save reopens its row. Archived rows offer Restore stage. Add stage is a quiet disclosure.
- **Appearance:** use a labelled native Theme select with System (default), Light and Dark. Apply and save immediately in browser local storage; no Save button, server restart or installation setting. Keep browser tabs in sync and follow OS changes only in System mode. The early head script applies the resolved `data-theme` before rendering; the shared theme controller maintains it. Palette tokens, native control color-scheme, Tailwind dark variants and contrast overrides must all follow the selected theme. Without JavaScript or available storage, retain the system fallback.

Workflow rules: archive blocks occupied/last-open-stage removal and links to current jobs. Restore appends within type and exposes name collisions for correction. Closure uses Checkbox and locks while referenced. Add/rename use Field/Input and unsaved-edit protection. Confirm starting-stage changes with ConfirmDialog plus native fallback; keep drafts/errors adjacent, preserve focus and do not require restart. These data controls use ordinary authenticated access, including allowed LAN browsers; do not reuse host-only maintenance gates.

- **LAN access:** show saved startup preference and effective running mode separately, with Restart required when they differ. Confirm Allow LAN access with the reachable-device/optional-password/HTTP warning, then offer Restart now/Later. Disable saves local-only mode but keeps effective phone addresses visible until restart. Show interface-labelled selectable addresses, Copy with manual fallback, and guidance to use the host shortcut for unavailable controls. Never label a VPN candidate as confirmed Wi-Fi. After restart, force a full page reload; fragment navigation cannot replace stale state or enforce renewed sign-in.

- **Password:** optional password-only login. Use Field/Input for passwords and hours, Checkbox for No expiration, and ConfirmDialog for disabling protection/logout-all. Signed-in host users can disable protection in Settings with the current password and confirmation. Forgotten-password recovery is host-command-line-only; Sign in has a Forgot your password disclosure with recovery instructions and an explicit MCP limitation. Log out and Log out all devices stay together in Settings; native logout/disable navigation clears client state. Enhanced forms preserve drafts on authentication-required responses and offer separate-tab sign-in.
- **Assistant:** show copyable JSON/TOML, built-entry status, and installation/dataset/build identities. Distinguish configuration prepared from real-client verification. Copy actions do not modify client files; instructions belong in the [assistant guide](assistant-guide.md).
- **Backups:** one Back up now action with Database and files / Database only / Files only. BackupList groups pairs with Download, Restore, and confirmed Delete. Partial entries show an available-artifact download. RestorePreview shows the selected contents and warnings. Independent import/additive restore/unmatched folders belong in Advanced file recovery. No schedule/retention panel.
- **Storage:** copyable data directory with Open folder; failure preserves the path and shows an error Notice. Keep build, storage versions, descriptor/log/backup/recovery paths in collapsed Diagnostics. Do not display secrets; distinguish build identity from a published release version.
- **Server:** Restart is regular; Stop confirms and explains reopening. Poll installation/generation readiness for a bounded interval before reloading; show logs/reopen guidance on timeout. Do not invalidate while shutdown is in progress. Without JavaScript, show accepted state and manual recovery guidance. Start at login uses the shared Checkbox and Save startup setting; read actual OS registration, disable unavailable controls, and explain sign-in/no-browser/Stop behavior.
- **Updates:** show installed/target identity, check errors, and local-change state. Confirm the selected target. Poll only active requested operations, with bounded timeout and recovery guidance. Uninstall defaults to retention; data deletion previews exact directories and requires the unchecked option plus `DELETE DATA` in the confirmation dialog. Wrap paths and preserve focus on errors.
- **Extensions:** use the existing directory and lifecycle controls; shared core design still applies. See the [extension guide](extension-guide.md) for the public component exports.

Dataset-mismatch notices explain that files are retained, user documents remain available, and job attachments need matching backups. Do not offer automatic rebinding or opaque dataset IDs as editable controls.

## Icons, motion, and accessibility

Use individual `@lucide/svelte/icons/...` imports. The root provider defaults to 20px, 2px stroke, and `currentColor`; inline button icons use the existing 16px styling. Icons reinforce visible labels. Keep decorative icons hidden from assistive technology. The Saturday logo remains a separate brand asset; do not add another icon library.

Route changes use a short View Transitions cross-fade; sheets/toasts use brief ease-out motion. Respect reduced motion, reduced transparency, and increased contrast. Browser support determines which OS preferences propagate. Without backdrop-filter, surfaces remain solid. Do not assume CSS blur automatically provides adequate contrast.

Before completing UI work:

1. Format changes, run `npm run check`, and run relevant tests, including `tests/ui-conventions.test.mjs` for UI changes. That test enforces shared labels/selects/choices, radius tokens, readable text, PageShell, back links, pagination, filters, confirmations, and enhanced-form progress. Change a convention only with its guide and test.
2. Review desktop/narrow layouts, long content, 200% zoom, light/dark, keyboard navigation, validation focus, dialogs, toasts, tab-bar scrolling, and reduced-motion/contrast/transparency preferences. Include 320px, 640px, 767px and 768px dialog widths to check stacked actions and the exact sheet/desktop boundary. Use disposable database and file roots.
3. Confirm required cues, errors, progress, success feedback, and unsaved-edit handling for new forms. Update the [user guide](user-guide.md) for user-visible behavior.

Browser review, contrast inspection, and actual screen-reader testing are separate from compilation and HTTP checks. Full platform accessibility verification remains pending.
