# Verify Saturday

## Launch and isolate

Run from the checkout being verified. Read `AGENTS.md` first. Never use the personal Saturday installation, its MCP connection, or its running server. Use only the public `tests/run.mjs` runner, including for focused tests. Do not invoke test files or internal sandbox guests directly. Missing sandbox protection stops verification; there is no unprotected fallback.

Use the checkout's existing Node >=22.13 and dependencies. If dependencies are absent, follow the repository/user dependency policy rather than silently installing host packages. Do not symlink another checkout's node_modules. Build the exact source before browser checks:

```sh
node tests/run.mjs -- npm run build
```

The runner creates disposable stores and enforces the OS filesystem boundary. Each mapped browser test seeds fictional data, chooses a loopback port, starts its own server, waits for a successful HTTP response, and launches Puppeteer. No separate persistent dev server is needed. Tests close their browser, terminate their owned child, and remove temporary data in `finally`; the outer runner removes its scratch tree. Separate invocations have separate stores/ports; avoid simultaneous builds in one checkout.

## Doctor

Inspect, without connecting to personal services:

```sh
node --version
git rev-parse HEAD
git status --porcelain=v1 --untracked-files=all
node -e "for (const p of ['node_modules/puppeteer/package.json','tests/run.mjs']) if (!require('node:fs').existsSync(p)) throw new Error('Missing '+p)"
```

Run the build through the public runner above and require exit zero. Its output must identify the isolated test workspace and platform protection. The journey's readiness assertion proves its own app instance responds; doctor/build alone does not prove a feature works. Require the selected test to execute with zero failures and zero skips; missing Chrome or a skipped browser journey is blocked, not passed.

## Drive

Use [the feature index](features/README.md) to select checks affected by the change. The initial mapped journeys are:

```sh
node tests/run.mjs -- node --test tests/job-duplicates.integration.mjs
node tests/run.mjs -- node --test tests/reminders.integration.mjs
node tests/run.mjs -- node --test tests/document-editor.integration.mjs
```

A focused journey is not a release certification. For changes spanning these surfaces, run every affected journey. Use `npm run test:web` for the full web suite and `npm run verify` only when the task/release requires it. Keep existing release rules intact.

## Evidence

Before execution create a unique private run directory outside the checkout and runner scratch tree, under a private evidence root outside the checkout and outside version control — this workflow uses
`$OPENCLAW_WORKSPACE/artifacts/verification/saturday/<run-id>/`, where `OPENCLAW_WORKSPACE` is the
assistant's private workspace. Never commit that directory. Redirect each public-runner command's stdout and stderr into its own log there and record its actual exit code; do not pipe into a logger that masks failure.

Write `evidence.json` with repository path, base/head SHA, dirty status, SHA-256 of `git diff HEAD --binary`, identities of relevant untracked inputs, Node/build identity, selected acceptance conditions, commands, exit codes, observed results, and relative log paths. For an entirely clean tree, record untracked inputs as an empty list. For dirty trees, identify staged, unstaged, and relevant untracked contents; a HEAD value alone cannot identify the verified code.

Read each log's test totals and assertions before assigning an outcome. Record `passed`, `failed`, `blocked`, `not run`, or `stale`; never call a skip a pass. Re-read revision and content identities after the run and before delivery; changed code requires affected checks to be rerun. Build output is generated by the recorded build command, not inferred from a pre-existing `build/` directory.

These existing tests write some screenshots into temporary paths that the runner deletes. The durable evidence in this pilot is the executed browser assertions and retained logs, not retained screenshots. If visual proof is required, explicitly export screenshots from inside the protected run before cleanup with a reviewed harness extension; do not weaken isolation or claim the screenshot exists afterward.

## Cleanup and report

Wait for the public runner to exit, then verify its printed scratch workspace no longer exists. Failure or interruption may leave evidence/scratch; report it and inspect owned resources, never kill processes by name. Keep the durable logs and manifest and verify they remain readable after cleanup. Do not delete the review worktree automatically.

Report the exact revision/content identity, journey outcomes, failure or skip reasons, evidence location, and limits. This macOS pilot says nothing about physical devices, other OSes, real assistant clients, or unexecuted journeys. Keep private evidence out of public commits.

## Maintain

When a route, selector, or behavior changes, update the mapped journey and its feature note together. Execute the revised instructions once before presenting them as ready. Existing failures are recorded, not silently weakened or fixed outside scope.
